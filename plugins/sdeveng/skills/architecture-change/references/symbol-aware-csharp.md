# Symbol aware C# change review

Use the current checkout and its detected project/framework facts. `sdeveng dotnet semantic-model --project PATH --json` accepts the solution path and reports C# declarations, project edges, references, and call sites when every project has a complete semantic compilation. It does not edit code. Stable declaration keys use Roslyn documentation IDs (for example, `T:Example.Store` and `M:Example.Store.Read`); source evidence uses repository-relative `path:line:column` locations. Confirm the installed SDK and target frameworks from project inspection instead of inferring them from this procedure.

Before proposing or reviewing edits, resolve every requested target to an exact stable key and source location in the current semantic model. Match the requested symbol kind, containing type, signature, and path. A missing key or a location that no longer identifies the requested declaration is stale: refresh the model and ask for a new target when intent is no longer exact. If multiple declarations satisfy the request, report the candidate keys and locations and stop for disambiguation. Never choose the first textual match or resolve by name alone. Treat incomplete semantic compilation as unavailable evidence; do not substitute text search as symbol proof.

Write a bounded ChangeSet before implementation. It names the allowed paths, exact symbol keys, intended responsibility/dependency change, expected call-site or project-edge changes, and focused validation. Keep unrelated symbols and files out of scope. Preserve existing public API signatures, visibility, and behavior unless acceptance explicitly authorizes a change; list any authorized public API delta and its compatibility evidence explicitly.

For review, compare the actual diff with the ChangeSet and report any changed path or symbol outside its bounds. Review evidence must identify each changed declaration by stable key and final repository-relative `path:line:column`, with the relevant before/after signature or dependency edge and the focused proof result. Cite evidence at the declaration or dependency edge being discussed, not only the file or diff summary. Re-resolve symbols after edits because line locations can move. Report missing, stale, ambiguous, or out-of-scope targets without silently widening the ChangeSet; do not claim unobserved proof. This procedure guides analysis and review; it does not provide an edit engine.
