# Symbol aware API compatibility review

Use the current checkout and its detected project facts. `sdeveng dotnet semantic-model --project PATH --json` reports declarations, references, and call sites from Roslyn when every project has a complete semantic compilation; it does not edit code. Resolve each requested or changed public declaration to its stable Roslyn documentation ID and repository relative `path:line:column`. Confirm public visibility, containing type, signature, and project before treating a declaration as an API change. A missing or moved anchor is stale: refresh the semantic model and stop if intent is no longer exact. If multiple declarations match, report their keys and locations and request disambiguation. Incomplete semantic compilation is unavailable evidence; text search is not a substitute for symbol proof.

Bound the work before editing: list allowed paths, exact symbol keys, intended change, affected callers or project edges, and focused proof. Preserve public signatures, visibility, and behavior unless acceptance explicitly authorizes a delta. For an authorized delta, identify the compatibility decision and relevant consumer impact. Inspect configured PublicApiAnalyzers baselines or package validation only when present; `sdeveng dotnet api-check --project PATH --json` refuses absent baselines or analyzers. Review diagnostic IDs and baseline changes; never accept generated baseline changes automatically.

After edits, resolve changed declarations again and compare the diff with the bounded change. Review evidence names each changed declaration by stable key and final `path:line:column`, gives before and after signatures, explains the compatibility impact or preservation, and records focused proof. Report stale, ambiguous, incomplete, or out of scope evidence without widening the change. This procedure guides analysis and review; it does not apply edits.

## Versioned repository facts

The semantic model is the current checkout's Roslyn fact source, not an API compatibility verdict. Its implementation and command contract are owned by the sdeveng producer and can evolve independently of this skill. Detect SDK, target frameworks, analyzers, and package baselines from the current project; do not infer framework APIs or versions from this procedure. Consult the pinned official .NET source inventory in `plugins/sdeveng/references/dotnet-skills-provenance.md` only when evidence selects a framework-specific package, trimming/AOT, or ABI/P/Invoke branch. No upstream implementation or framework API claim is copied here.
