# Verification results

[`verification-result-v2.schema.json`](../../schemas/verification-result-v2.schema.json) defines the current outcome. It records source (`local` or `hosted`), exact check, passed, failed, cancelled, or timed-out status, exit code, evidence artifact, and environment identity. Exit code zero means passed; a positive exit code preserves the observed nonpassing state. Local results use the machine name; mapped GitHub checks use `github:owner/repository@commitSha`. The [version 1 schema](../../schemas/verification-result.schema.json) remains readable for older passed/failed results.

Local commands run through `AgentTool.RunArtifact` include a `verification` object in their existing process report. Dotnet build, test, format, and pack commands use the shared check names `build`, `tests`, `format`, and `package`, so local and hosted evidence for the same commit can be compared. The report's existing exit code, summary, and artifact remain available. `VerificationResults.FromGitHubCheck` preserves completed GitHub check success, failure, timeout, and cancellation outcomes; action required is failed. Pending and indeterminate conclusions cannot produce a result. The check's HTTPS details URL is its evidence artifact.

`VerificationResults.Evaluate` compares at most one local and one hosted result for an exact check. The final PR workflow calls `verification decide` on its exact-head `commit-ci-result` artifact and the required checks in `config/verification-evidence-policy.json`. The command can also read an optional exact-commit local bundle to expose local/hosted disagreement. Progression requires each configured source, at least one result, no failed result, and agreement whenever both sources are present. The decision identifies disagreement and gives stable reason codes; its serialized shape is defined by [`verification-decision.schema.json`](../../schemas/verification-decision.schema.json). Missing or inconclusive hosted checks remain absent evidence rather than being treated as passing.
